## 4. 容量、碰撞优化与低层控制

4096环境下继承官方`max_gpu_contact_pairs=2**23`出现遗漏碰撞交互；buffer倍率5→32无效。V3专用容量改为`2**25`、倍率仍5，最终身份重测通过。该变化属于物理容量修正，不改官方副本。

927→80 shape训练候选减少了复杂CAD求解成本，最初合并会填轮拱／型材间隙；按局部部件拆分后通过当时门控。早期错误源码副本缺文件和容量覆盖，不能作为最终身份依据。最终80-shape身份4096×100完整平均4.0301秒／轮，8000更新段估算8.96h；这是旧几何／5ms控制下的测量，不能当成后续V6训练耗时。旧927-shape正式训练在1423轮停止，最近完整权重1400，数据和检查点保留。

后续确认reset后刚体TCP缓存过期，目标初始点偏差显著，重复refresh不能修复；改为当前root／DOF独立FK，误差恢复至约1e-7m。train_v5轮胎接触不平滑、活动归属及轮胎零位支撑不共面造成承重和运动异常；独立平滑胎面后平移改善。四轮底点最佳支撑面差约4.53mm、右后轮离地约8.3mm；用户批准仅碰撞半径微调，V6 r2最大改动2.2637mm，共面残差约9.389e-8m，视觉／关节／物性保留。

偏航问题又涉及显式速度反馈的离散稳定性；5ms更新下增益提高20%会饱和振荡，单纯延长静置或转向加倍未通过。最终采用物理／PD 2.5ms×8，策略仍20ms，驱动反馈7.73109Nm·s/rad、转向刚度49.8436Nm/rad。正反偏航MAE 0.041247／0.039031rad/s、平移最大0.015808m/s、base接触0N，满足原0.05rad/s和0.03m/s门槛。32环境、reset、512×10＋跨进程恢复、4096容量与四阶段门控通过。4096×20完整PPO平均9.4071秒／轮，约20.9h仅为当时估算。

探针曾有GPU分支不推进物理、将post-step反馈误称真实施加力矩的问题，已统一推进并记录真实子步力矩；无效旧探针不能当物理证据。最终报告为`.scratch/unifp-v3-stage1-reproduction/knowledge/model_history/unifp-v3-a8000-diagnosis/artifacts/t04/T04-最终验收报告.md`。
