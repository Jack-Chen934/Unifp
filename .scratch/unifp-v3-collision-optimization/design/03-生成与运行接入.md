# 03 生成与运行接入

已确认总结：新增一个直接的离线资产生成工具，沿用当前 manifest 的计数与局部安装分组接口，尽量复用现有运行链；新资产通过后再切换配置。用户已确认并要求实施。

## Q1 生成调用链和接口是什么？

当前：`桌面 ZIP → build_desktop_asset → 每 CAD 连通件一个碰撞 → v3_a1_desktop`。

目标：`已验收 v3_a1_desktop → build_training_collision_asset → 保留视觉／物性／运动链、按功能生成代理 → v3_a1_desktop_train_v1 → 原 V3 创建链`。

最小接口草图，只有职责和签名，不包含业务实现：

```python
def build_training_collision_asset(source_root: Path, output_root: Path) -> Path:
    # Copy preserved fields; emit named collision proxies and manifest.
    ...

candidate_urdf = build_training_collision_asset(source_root, candidate_root)
candidate_config.asset.file = str(candidate_urdf)
environment = V3PosForce(candidate_config, sim_params, physics_engine, device, True)
```

输出为独立 URDF 路径，目录包含引用的视觉文件、代理凸网格及 `asset_manifest.json`。使用显式盒体尺寸、凸网格坐标和名称表；不建立通用拟合插件、运行期自动切换或多级配置框架。已存在的输出目录不可静默覆盖。

## Q2 如何兼容现有碰撞过滤？

**推荐：**新 manifest 继续提供 `collision_solid_counts[link].count` 和 `source_groups`。底盘四处固定安装件分别输出为 `fl_fixed_collision` 等组，不与主壳体合并；轮体及固定手指保持名称和过滤职责。原 `apply_desktop_assembly_filters` 可据新 count／索引工作，预计无需修改其业务逻辑。

新增近似来源字段记录代理与原 CAD 组件的对应关系，不能把代理组索引伪称为原网格三角面编号。Gym 导入后核对 shape spans，避免 primitive 或 importer 分解使 XML 元素数与实际 shapes 不一致。若既有过滤接口无法表达必要的局部规则，先回写本议题，不直接扩大豁免范围。

## Q3 如何确保碰撞简化不顺带改变惯量？

**推荐：**所有 link 的 URDF inertial 保持原值，分别记录新旧 actor 的实际 mass／COM／inertia；验证包含导入、父类提交和创建期随机化后的结果。

父类现有 `recomputeInertia=True` 路径必须实测核对；若碰撞改变导致实际惯量偏离，不能只凭 XML 一样就验收，也不能默许自动重算。届时记录差异并单独讨论最小 V3 局部修正。本草案不提前修改通用 base 创建链。

## Q4 哪些源码预计涉及？

**推荐：**新增 `tools/build_training_collision_asset.py`、针对候选的必要静态／物理／性能检查；最终接入只修改 `v3_pos_force_config.py` 的资产路径及相关测试入口。原生成器、官方代码、Actor、Critic、PPO 和日志不因这次碰撞优化而重写。
