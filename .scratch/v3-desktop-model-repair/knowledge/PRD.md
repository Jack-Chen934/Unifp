# V3 桌面资产基准修复任务

## 目的

以桌面文件`/home/sorry/桌面/a1arm_description.zip`中的机器人外观及整机框架为最终基准，检查当前`UniFP_v3`运行资产与之的结构、物理属性和碰撞差异，形成可追溯的修复资产。用户指出桌面版本的基本框架正确，主要问题是质量参数和车轮不可动；该约束覆盖此前“以归档V3 movable资产派生”的默认资产选择。

## 范围

本任务聚焦桌面压缩包中A1机械臂与Ranger Mini 3组合模型，核查URDF和引用网格，明确视觉外观基准、自由底盘根、四轮转向／滚动关节、质量／质心／惯性以及碰撞几何。资产输出应独立放入`UniFP_v3/resources/robots/`并记录源和派生哈希；归档官方代码、旧V3和桌面压缩包只读保留。

## 当前调用关系

`V3PosForceCfg.asset.file`选择开发资源URDF → `LeggedRobot._create_envs()`调用Isaac Gym导入并创建actor → V3环境按14维策略动作映射转向、轮驱动和六臂关节。当前实现资产是从归档`a1arm_rgm3_original_movable.urdf`派生，只固定两指关节。桌面压缩包的`a1arm_rgm3.urdf`尚未被运行时采用。

## 约束

- 最终可视外观以桌面压缩包为准；不能因为当前派生模型已存在就沿用其外观。
- 用户指出桌面模型主要有质量和轮子可动性问题；其他基础框架结构作为正确基准，任何额外运动链／碰撞／安装位置改变必须有证据和记录。
- 质量来源须区分厂家公开整机规格、项目估算、资产实测和物理引擎回读；不能把集中质量估算说成实机分布标定。
- 必须保留其他非相邻自碰撞；当前接触诊断只针对当前开发URDF，不能直接归因到桌面URDF。
- 先完成知识、设计与实施票据的逐项确认，再修改运行资产或业务配置。

## 完成含义

确定桌面外观资产与其哈希；运动学拓扑符合自由底盘＋4转向＋4轮驱动＋6臂关节（夹爪按A阶段设计固定）；质量／质心／惯性来源清楚；无初始几何穿透造成的异常高力；在Isaac Gym中成功加载、回读属性，完成轮组关节运动、静置接地、自碰撞和reset短测；运行manifest记录所有几何、物理和配置差异。未经整体验证不得称为训练可用模型。
