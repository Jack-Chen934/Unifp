## 架构层接口契约

下表记录本模块确认的装配边界。`N`是并行环境数；`A`是动作维度；`O`、`C`、`P`分别是展平Actor观测、Critic观测和辅助标签维度。维度数值及字段语义由议题03—06确定，不能从旧版本自动继承；`N`及设备在议题02确认。它们不是本模块新增的配置字段。

| 调用边界 | 签名／数据契约 | 归属与验证位置 |
|---|---|---|
| 新训练脚本 | `train(args: argparse.Namespace) -> None`；接收已解析命令行参数，运行训练并写输出 | 沿官方入口职责，参数字段与合并顺序在议题02，运行状态在07落实 |
| 新评估脚本 | `evaluate(args: argparse.Namespace) -> None`；必须明确模型来源和协议，写评估数据，不更新模型 | 具体参数及评估记录接口在议题10；本模块只确定独立入口职责 |
| 任务配置 | 现有 `get_cfgs(name) -> (env_cfg, train_cfg)`，以新V3任务名注册配置和环境 | 参数所有权、隔离和覆盖在议题02；不额外增加配置服务层 |
| 创建环境 | 现有 `make_env(name, args=None, env_cfg=None) -> (env, env_cfg)`；由配置构造Gym任务，显式传设备与headless | 资产、环境签名、状态初始化及失败条件在议题03／04 |
| 创建学习Runner | 现有 `make_alg_runner(env, name=None, args=None, train_cfg=None, log_root="default") -> (runner, train_cfg)` | 沿官方链路，显式设置输出根；恢复及迭代语义在议题07 |
| 环境步进 | `step(actions[N,A]) -> (observation_dict, reward[N], done[N], infos)`；观测含obs[N,O]、privileged_obs[N,C]、obs_pred[N,P] | 这是官方实际四返回值契约，具体dtype、reset时序、单位及坐标系在议题04确认；不依抽象VecEnv过时标注推导 |

入口自身没有物理单位；物理量及坐标变换属于环境和评估记录，必须在议题03、04、08、10逐字段定义。策略输出是映射前的动作向量，不能在此称为统一的角度或力矩单位。
