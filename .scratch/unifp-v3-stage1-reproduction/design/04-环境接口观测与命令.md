## 已知依据

官方B2的`step`实际返回四项`(obs_dict, rewards, dones, infos)`，其中`obs_dict`含`obs`、`privileged_obs`和`obs_pred`；Runner取三个字段分别交给策略、Critic和监督训练。官方Actor为73×32、Critic149×3、标签12；这些尺寸不能自动成为V3目标尺寸。

## 讨论记录

### Q1 · 环境公开接口、数据所有权与reset语义

问题：是否采用下面的V3交接协议，保留官方step的四项返回与三个观测键，同时明确reset和终止数据的含义？

推荐：采用。让环境准备完整的数据包；Runner继续使用现有读取方式，避免把仿真细节分散到学习器或增加桥接层。

#### 接口与数据契约提案

N为并行环境数，A=14；O、C、P为待Q4—Q5／05—06确认的Actor历史、Critic历史和监督标签宽度。本表是设计类型，不引入新的运行时包装类。

| 签名 | 返回／输入与约束 |
|---|---|
| `V3PosForce.step(self, actions: torch.Tensor) -> Tuple[Dict[str, torch.Tensor], torch.Tensor, torch.Tensor, Dict[str, Any]]` | 输入float32[N,14]无量纲动作；返回`obs_dict, rewards, dones, infos`，不改为五项Gymnasium协议 |
| `V3PosForce.get_observations(self) -> Dict[str, torch.Tensor]` | 返回最近一次完成的观测包；`obs`为float32[N,O]、`privileged_obs`为float32[N,C]、`obs_pred`为float32[N,P]；不推进物理、不重采样命令或噪声、不追加历史 |
| `V3PosForce.reset(self) -> Tuple[Dict[str, torch.Tensor], Dict[str, Any]]` | 全量重置，返回`obs_dict, reset_infos`；第二项明确为重置信息，不伪称特权观测。保持两项以兼容Runner的`_, _ = env.reset()`，V3评估器按明确签名读取 |
| `V3PosForce.reset_idx(self, env_ids: torch.Tensor) -> None` | 环境内部的局部重置，输入一维long[K]，公开reset只做全量；不引入多种env_ids类型或可变返回形式 |
| `V3PosForce._refresh_reset_kinematics(self, env_ids: torch.Tensor) -> None` | 从刚写入的root／DOF状态和已加载运动链，重建reset环境所需的TCP等运动学派生量；不得读取上回合未刷新的body值当新真值；仅为reset内部接缝，不增加策略观测 |

`rewards`为float32[N]；`dones`为long[N]且只含0／1，沿现有存储习惯；`infos['time_outs']`为bool[N]。训练与正式评估三类观测键始终存在，Actor推理只消费`obs`，不因字典里还有特权输入就将真值传入Actor。评估器可读取真值计算指标，其数据权限由10定义。

#### 设备与数据所有权

- 环境、策略及所有返回张量位于同一显式设备；正式运行遵守02的单GPU约束。不在`step`里隐式CPU／GPU转换以掩盖配置错误。
- `get_observations`读取当前缓存，不改变时间、噪声或历史；同一时刻重复调用应得到同一数据。
- 每次发布的观测／标签张量保持只读语义：下一次`step`和reset不得原地覆盖仍可能被`PPO.transition`引用的旧`obs_t`。采用每次构造新观测张量的直白方式，无需复制完整模拟器状态或新增版本化缓存框架；调用方也不得原地修改环境输出。
- `infos`每次重新组装，跨reset需要保留的done、超时标志和终止数据独立保存，不能引用随后清零的临时视图。测试需保留旧输出后推进下一步，验证旧样本未变化。

#### 策略步与reset时间语义

```text
动作前：obs_t／privileged_obs_t／obs_pred_t → PPO.act → a_t
物理步：同一a_t保持4个5ms子步，执行器每子步更新
步完成：读取reset前的s_(t+1)，计算本转移reward_t、done_t、timeout_t
        → 保存需要的终止信息 → 只重置done环境
        → 为存活环境构建obs_(t+1)，为done环境构建新回合obs_0
        → 发布下一观测包、reward_t、done_t、infos_t
```

返回观测可包含已reset的新回合初始值，但本步reward／done仍属于刚结束的转移。`obs_pred`必须对应它所伴随的观测时刻，不能将终止前标签与reset后Actor输入配对；真实终止前快照通过单独的infos通道保留，详细字段／条件在Q7确认。

推荐V3的公开reset不额外调用完整`step`：只写入状态、初始化命令和计数、刷新对应运动学并构建首帧。不能为“刷新body”推进四个物理子步、产生奖励或消耗课程计数。reset后物理接触尚未产生时，接触缓存清零属于初始化状态；如何对Critic／历史表达该时点由Q5／06明确，不伪称上一回合接触就是当前测量。

此处新增reset运动学接缝是为了避免官方注释中“可能需要模拟一步刷新body”的问题；若实际Gym能在无时间推进下可靠更新所需量，使用该能力并做等价性验证，避免重复实现多套运动学。

#### 当前与目标调用链、失败与测试

当前：`Runner.__init__ → BaseTask.reset → reset_idx → 零动作step`；`Runner.learn → get_observations → PPO.act → step → reset_idx → compute_observations`。

目标：`Runner.__init__ → V3.reset → reset_idx → reset运动学／首帧构建 → (obs_dict, reset_infos)`；训练保持`get_observations → PPO.act → step四项返回 → PPO.process_env_step`。B2入口与BaseTask不全局重写；如需公共接口类型更正，在07单独明确最小改动。

输入shape／dtype／设备／非有限值错误在物理推进前失败，指出期望和实际值；不裁剪NaN继续。合法动作饱和沿03规则。缺失观测键或模型维数不匹配在首次训练／推理前失败。原始仿真非有限状态按03终止，不把它视为普通episode终止。

测试接缝包括：不依赖Gym的返回契约检查和时间标记已知样本；局部reset隔离；旧输出跨step保持不变；重复读取不改变噪声／历史／计数；真实环境的首帧与reset后FK／标签一致性；Runner初始化和一次收集贯通。最终测试时长与容差在11确认。

本题不改变PPO的超时计算公式。官方`process_env_step`当前使用旧V补偿超时奖励，是否改为真正终止前Critic观测的V由07讨论；保留`time_outs`和末帧读取能力不等于已修复或已批准新bootstrap算法。

## 接近真实调用关系的最小框架（Q1提案）

```text
reset() -> (ObsDict, reset_infos):
    reset_idx(全部环境)
    _refresh_reset_kinematics(全部环境)
    构建初始观测／标签与历史，发布只读观测包
    return get_observations(), reset_infos

get_observations() -> ObsDict:
    return 最近发布的obs／privileged_obs／obs_pred

step(actions[N,14]) -> (ObsDict, rewards[N], dones[N], infos):
    物理推进前检查输入
    按03执行四个物理子步
    读取reset前派生状态，计算本转移奖励／终止／超时
    保存需要的终止信息
    reset_idx(done环境)
    _refresh_reset_kinematics(done环境)
    按存活／reset时刻构建下一观测与同刻标签
    return 发布观测包, 本转移奖励, 本转移done, 独立infos
```

字段的具体切片／归一化／frame／历史长度和终止条件将在后续问题补齐；当前不将未讨论内容写成目标实现。
