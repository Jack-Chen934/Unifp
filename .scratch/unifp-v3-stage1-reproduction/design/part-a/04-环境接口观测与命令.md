## Q1 · 公开接口、数据所有权与reset

**问题：如何保留官方训练链，并消除reset和缓存歧义？**

**推荐答复：保留step四项和三个观测键，明确reset第二项为信息字典，reset不产生隐藏物理步。**

设N为环境数，K为本步done数量，D=14，O=1856为已确认Actor总宽度，c=98为A06-Q4d已确认Critic单帧宽度，C=3c=294，P=12。浮点张量均为float32、与环境处于同一显式设备；签名中的Tensor不另包装运行时类。

| 接口 | 输入／输出契约 |
|---|---|
| `V3PosForce.step(self, actions: torch.Tensor) -> Tuple[Dict[str, torch.Tensor], torch.Tensor, torch.Tensor, Dict[str, Any]]` | 输入[N,14]无量纲策略动作；返回`obs_dict, rewards, dones, infos`，保持官方四项协议 |
| `V3PosForce.reset(self) -> Tuple[Dict[str, torch.Tensor], Dict[str, Any]]` | 全量重置并返回初始观测、`reset_infos`；不调用step，不simulate，不消耗策略步／rollout／课程计数 |
| `V3PosForce.get_observations(self) -> Dict[str, torch.Tensor]` | 只读最近发布的观测包，不采样噪声、不重采命令、不追加历史 |
| `V3PosForce.reset_idx(self, env_ids: torch.Tensor) -> None` | 内部局部重置，输入long[K]；仅改变所选环境的episode状态，不清零全局学习／课程计数 |
| `V3PosForce._refresh_reset_kinematics(self, env_ids: torch.Tensor) -> None` | 从刚写入的root／DOF状态和模型运动链重建TCP等量，禁止拿旧body缓存当reset后真值 |

`obs_dict`固定三个键：`obs[N,O]`、`privileged_obs[N,C]`、`obs_pred[N,12]`。其中`obs_pred`是环境监督标签，名称沿官方，不能当作网络预测值。`rewards[N]`为float32，`dones[N]`为long且仅0／1；`infos['time_outs'][N]`为bool。Actor只读取`obs`；评估可用真值算误差，但不能送入Actor。

每次发布重新构建观测／标签张量和infos；奖励、done及终止快照也不得在后续step／reset被原地覆盖。调用方对已发布包只读，PPO自己的转移存储仍由A07管理。无需复制整个模拟器，也不新增缓存版本管理框架。

reset写入状态后，如Gym能无时间推进刷新所需运动学且已验证，则直接使用；否则采用与运行资产一致的FK及速度运动学。后者必须包含root／关节速度对TCP点速度的贡献，而非仅算末端位置。未产生新接触时接触数据置零，这是初始化状态，不沿用旧episode接触。

**取舍：**需要覆盖V3的reset和少量数据交接逻辑，但不全局改写B2或添加Gymnasium／Lab桥。只更正接口类型、首帧和缓存生命周期，学习算法问题继续留A07。

**用户答复（2026-10-31，整组确认）：**“同意这几个议题，但要详细记录与原文相比改了什么，没改什么”。

**已确认结论：**保留step四项／三个观测键；reset两项且无隐藏物理步，明确首帧运动学、输出所有权和局部reset边界。

## Q2 · 坐标系、单位与策略步时序

**问题：哪些量使用完整机身坐标，哪些量使用仅yaw坐标，动作和标签如何对时？**

**推荐答复：显式使用W／B／Y／T四个坐标约定，任务量不混用完整机身旋转与仅yaw旋转。**

| 记号 | 定义与用途 |
|---|---|
| W | Gym全局世界，z向上；位置已经包含环境原点，不重复加偏移 |
| B | base_link完整姿态坐标，x前、y左、z上；包含roll／pitch／yaw，线／角速度监督使用B |
| Y | 只随base yaw旋转的水平轴，x为水平前方、y左、z沿世界竖直；目标球坐标与力命令／力标签使用其轴 |
| T | 已确认绑定body上的TCP参考轴；TCP几何变换沿03，不能将T原点当COM |

四元数采用Gym的xyzw顺序。角度rad，角速度rad/s，位置m，线速度m/s，力N，力矩N·m，刚度N/m。转向和轮速采用03规范符号映射，观测、动作与日志使用同一命名顺序。

力变换为`F^W = R_z(yaw) F^Y`、`F^Y = R_z(yaw)^T F^W`；不对力向量减坐标原点。TCP点速度沿03由COM速度、角速度和当前力臂计算，reset时还须用一致的运动学重建。TCP球坐标位置使用Q6明确的球心，不能直接对世界位置做cart2sphere。

**推荐时序：**在策略边界t锁定命令`c_t`，Actor据`o_t`产生`a_t`；相同动作保持4个5ms子步，执行器每子步读最新关节状态更新力矩。A无人工施力；B仍每子步用当前TCP力臂，具体独立外力事件由B04／B09定义。末端命令力按20ms策略区间保持，不能在Actor看不到新命令时悄悄切换。

到达边界t+1：刷新物理量，以刚执行区间的`c_t`计算reward／失败；之后推进命令调度，形成下一边界命令`c_(t+1)`。先构造未reset的下一状态所需Critic末帧并保存done快照，再reset对应环境，最后发布存活环境的下一帧和新episode初帧。这样奖励不使用刚重采、尚未让Actor看到的底盘命令。目标在策略区间做零阶保持；插值值按20ms边界更新，此处明确记录相对官方更新顺序的工程差异。

`obs_pred_t`与同包`obs_t`对应：状态量是边界t真值，人工外力标签是刚结束区间最后一次实际施加的力，再变换到边界t的Y轴；初始／reset帧为零。不把下一步尚未施加的随机外力作为当前监督标签。B若需要平均力等不同目标，须先修改并确认该语义，不能保持名字却换标签定义。接触反力另记录，不能混成注入力。

**取舍：**保留官方的坐标和历史学习思路，同时显式修正命令／奖励边界；不额外增加目标速度、未来端点或时间倒计时到Actor。

**用户答复（2026-10-31，整组确认）：**“同意这几个议题，但要详细记录与原文相比改了什么，没改什么”。

**已确认结论：**采用W／B／Y／T坐标与统一单位；reward使用执行区间c_t，随后更新c_(t+1)，监督状态与上区间实际注入力明确对时。

## Q6 · 目标坐标、可达域与命令生命周期

**问题：如何保持官方球坐标任务形式，又避免照搬B2目标导致V3任务不可达？**

**推荐答复：保留球坐标当前目标与分段插值；球心采用V3名义臂座水平参考，reset从实际TCP开始，范围用本机工作空间核验后在A08冻结。**

设base世界XY为`p_base_xy^W`、yaw为ψ，平地参考高度为`z_ground`，名义base原点高度为`h_nominal`，臂座相对base的固定平移为`(x_mount,y_mount,z_mount)`：

```text
center^W = (base_x, base_y, z_ground + h_nominal + z_mount)
           + R_z(ψ) (x_mount, y_mount, 0)
p_geom^W = center^W + R_z(ψ) sphere2cart(r, elevation, azimuth)
s_tcp = cart2sphere(R_z(ψ)^T (p_tcp^W - center^W))
```

这里Y轴只跟yaw，球心高度不随base实际起伏／roll／pitch改变，延续官方要求保持水平任务目标的语义。它跟base XY与yaw移动，并非固定世界目标；若以后需要世界固定接触任务，由B场景明确设定，不得把两种跟踪混为一条曲线。

由现有资产推得候选`x_mount=0.174m, y_mount=0, z_mount=0.09535m`；若名义base高0.32m，则候选球心高为离平地0.41535m。这是资产几何派生候选，等待03物理短测回读／冻结，不是已批准最终高度；环境世界位置已含原点，`z_ground`只计一次。

球坐标约定：`x=r cos(elevation) cos(azimuth)`、`y=r cos(elevation) sin(azimuth)`、`z=r sin(elevation)`；elevation相对水平面，azimuth从+x向+y。半径不得为零，cart2sphere使用有界／稳定计算；方位角插值走相邻端点的最短角差，避免跨±π绕大圈，并记录相对官方直接线性插值的差异。A08的保守任务域还须避开方位角±π接缝、r接近零和球坐标极点；训练／标签使用同一约定分支，不能以角度取模制造虚假的巨大监督误差。

**目标生命周期提案：**

1. reset先从新状态FK取得真实TCP球坐标，将其作为起点及当前几何目标；不读取旧body缓存、不照搬B2初始0.66m目标。若新TCP不满足预先验证的初始安全集合，视为初始化错误，不把它裁成另一位置继续训练。
2. 从已验证的保守工作空间中采样下一端点，保留官方球坐标分段插值／保持模式，候选移动时长1—3s、保持0.5—2s。每段重采时长，并换算为明确整数策略步；取整规则固定为向上取整，实际时长落日志。
3. 在策略边界更新当前插值值，发布给下一次动作。到保持结束，以上一段端点开始下一段，不按实际跟踪误差重置目标起点而掩盖落后。底盘命令候选每5s即250策略步重采；范围、零命令概率、小值清零阈值归A08／A09确认。
4. V3工作空间在当前关节限位／TCP／碰撞几何下核验，端点与插值路径均检查地面、机身禁入区和关节可达性。静态可达性筛查可使用离线FK／IK作任务验证工具，但不能把IK或轮速分配器加入在线策略控制路径。离散检查不等同连续碰撞保证，也不保证动态耦合下永不失败。
5. 重采候选最多10次；若没有通过验证的候选，报告环境、候选和拒绝原因并停止本次运行，不发出未验证目标，也不静默缩小任务范围。拒绝率写日志，过高时回A08调整已确认工作空间。

## Q7 · 失败、timeout、终止快照与局部reset

**问题：怎样区分物理失败、正常到时、仿真错误，并避免reset污染PPO样本？**

**推荐答复：episode失败与数值错误分开；终止数据在reset前保存，time_outs只标记纯到时截断。**

| 情形 | 推荐处理 |
|---|---|
| 正常轮地接触、预期工具物体接触 | 不据此done；A08奖励／B接触协议另处理，不把所有净接触力统一当失败 |
| 机身倾覆或base_link禁触碰撞 | episode失败；候选采用官方量级`abs(roll)>0.8rad`或`abs(pitch)>1.0rad`及base_link净接触力范数>1N；必须在V3物理短测验证阈值与映射，不宣称原本为V3安全标定值 |
| 普通关节／力矩合法饱和、打滑或TCP暂时跟踪误差 | 不在A04新增任意done门限；由A08明确奖励与任务边界，记录对应指标 |
| episode到时 | 候选20s，20ms周期为1000步；完成量`>=1000`到时。明确修正官方`>`导致的多一步边界，初始化reset不计时 |
| 失败与到时同时发生 | 以失败为主：done=1，terminated=True，time_outs=False，避免对真实失败做timeout bootstrap |
| 非有限root／关节／观测、Gym数值发散或非法接口 | 依03终止本次运行，保存诊断；不把NaN裁剪为有限数后当正常reset继续 |

倾角、接触阈值和episode时长已获准作为本组设计与短测候选，物理有效性及正式运行冻结仍待验证。碰撞body按名称映射并记录，不沿用B2的thigh／calf索引；B接触物体数量增加时仍使用sim域索引，不假定所有刚体恰好是N×机器人刚体数。工具接触的过滤／实际反力完整协议留B04／B10。

**infos最小契约：**

- `time_outs`: bool[N]，只含纯timeout；`terminated`: bool[N]，表示物理episode失败。`dones = terminated | time_outs`，转换为long[N]。
- `terminal_env_ids`: long[K]；`terminal_privileged_obs`: float32[K,C]，与ids逐行对应，来自尚未reset的下一物理状态及若继续episode本应使用的下一命令／Critic历史；不是reset后的观测，也不是旧V对应的输入。K=0时提供形状正确的空张量。
- `episode`: 仅在有结束episode时记录reset前的奖励汇总、实际长度和失败／到时统计；字段与正式日志由A07／A10收束。物理trace单独存，不把全量sim状态塞进每步infos。

Critic终止历史由上一时刻的历史加一帧边界t+1的干净末帧构造；它是候选下一状态，不向正式发布历史重复追加。假如命令恰在该边界重采，奖励仍用旧命令，终止Critic读取若无reset本应继续用的新命令。随后才为done环境采新episode初始命令、清空历史并发布初帧。

只reset对应环境的root／DOF、episode计时、目标段、动作／力矩／人工力、接触缓存、随机化episode状态和历史；存活环境不被清零，Runner的已完成迭代／累计样本／全局课程计数保持不变。reset后不能在post-step尾部再把刚结束episode的actions／last_*写回新episode。

本题提供正确终止输入和截断标志，**不直接批准新的PPO bootstrap公式**；A07须明确何时求terminal V、失败不bootstrap及rollout边界处理，并用独立样例验证。20s也是episode时长，8000是训练迭代，两者不能混计。

**用户答复（2026-10-31，整组确认）：**“同意这几个议题，但要详细记录与原文相比改了什么，没改什么”。

**已确认结论：**区分物理失败、纯timeout和运行错误；reset前保存终止Critic，失败优先，局部状态与全局计数隔离；阈值待短测，PPO公式归A07。

## 接近真实调用关系的最小接口框架（已确认设计，无业务实现）

目标位置为新V3环境文件`UniFP_v3/legged_gym/envs/v3/v3_pos_force.py`，配置字段位于同目录V3配置；尚未创建。除Q1已有签名外，建议以下内部接缝：

| 接口 | 主要职责与shape |
|---|---|
| `_advance_commands(self, env_ids: torch.Tensor) -> None` | long[K]，仅推进所选环境到下一策略边界的命令／目标调度，不simulate |
| `_build_frames(self, env_ids: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor, torch.Tensor]` | 从当前一致物理状态和命令读取干净Actor[K,58]／Critic[K,c]／监督[K,12]；无历史和噪声副作用 |
| `_publish_observations(self, env_ids: torch.Tensor) -> None` | 仅为所选环境采一次Actor当前帧噪声、追加历史并发布新的全量只读观测包；reset选择已清零的历史 |
| `check_termination(self) -> None` | 填充独立的failure／纯timeout／done缓存，不reset，不修改奖励 |

如实现能直接使用已确认的官方相应函数，则保留原名与职责，不为表格机械新增一层转发；A05／A06补齐数据字段时同步接口框架。配置shape由字段定义求和，不能再独立写死另一组58／1856／12常量。

```text
Runner.__init__
  → env.reset() -> (ObsDict, reset_infos)
      → reset_idx(all_ids)：写新root／DOF，清episode缓存，不清学习计数
      → _refresh_reset_kinematics(all_ids)
      → 初始化当前／下一目标及命令
      → _publish_observations(all_ids)：新历史最后一格为首帧

Runner.learn
  → env.get_observations() -> ObsDict（只读）
  → PPO.act(obs[N,1856], privileged_obs[N,C], obs_pred[N,12]) -> action[N,14]
  → env.step(action)
      → 检查输入，锁定本区间c_t，按03裁剪动作
      → 4 × [最新DOF反馈 → 请求力矩 → 当前TCP等效施力 → simulate 5ms]
      → 刷新物理状态／TCP／接触；episode已完成策略步加1
      → check_termination；compute_reward使用本区间c_t
      → _advance_commands(all_ids)，准备若继续episode的c_(t+1)
      → _build_frames(done_ids)，拼接终止Critic历史，冻结infos终止数据
      → reset_idx(done_ids)；_refresh_reset_kinematics(done_ids)
      → 为reset环境初始化新episode命令／目标
      → _publish_observations(all_ids)，每个环境仅追加一帧
      → return ObsDict, reward_t[N], done_t[N], infos_t
  → PPO.process_env_step(reward_t, done_t, infos_t)
      → storage保存旧obs_t／label_t／action_t及本转移信息
  → A07处理returns／PPO／辅助更新／完整checkpoint
```

本框架只固定职责与数据边界，不是提前实现业务代码。无新通用后端、传感器服务、在线IK控制器或轮式创新模块。
