当前`V3PosForce.step`在任一力槽非零时退出，子步只施加关节力矩。目标是在同一step/reset协议中实现独立命令力与人工外力事件，并将实际施力和标签按同一转移对齐。

actions = ppo.act(published_history[N,1856], published_critic[N,294], published_labels[N,12])

publish_next_observations_once() -> next_history, next_critic, next_labels
infos = existing_infos(terminated, pure_timeout, done_ids, terminal_critic, episode_records)
ppo.process_env_step(reward, done, infos)

### Q2：两路力是否采用独立梯形事件，每个策略边界更新一次？

状态：2026-11-07用户回复“同意”，确认以下机制及工程差异；未修改业务代码。具体幅值、概率、时间范围留B09，不因本项机制确认自动采用官方数值。

推荐机制：每个环境各自维护命令力和人工末端外力事件。两路分别随机抽样是否启用、目标三维力、事件起点间隔及上升／下降时长；可重叠、可单路启用、可同时零力，不强制相等／相反或同步启停。不增加配对比例等额外训练超参数；专项匹配力对照由B10固定。

采用官方形状：零力→线性上升→保持→线性下降→零力。设事件年龄u、上升／下降时长r、保持时长h、目标向量F_peak，推荐明确的边界公式为：

```text
0 <= u < r       : F = (u/r) * F_peak
r <= u < r+h     : F = F_peak
r+h <= u < 2*r+h : F = (1 - (u-r-h)/r) * F_peak
2*r+h <= u      : F = 0
```

事件间隔I定义为相邻计划起点之间的时间；限制r <= (I-h)/2，保持一条流内部不重叠。启用概率未选中的计划周期全程零力，仍按计划到下一次重新抽样。该设计不把配置中的duration误当作“整个事件长度”；总非零事件包络为2r+h，剩余为零力等待。

每20ms边界只推进／采样一次事件，将本边界命令写入即将供Actor决策的观测；策略随后产生动作。8个2.5ms物理子步复用同一事件幅值，不在每个子步重新采样。事件幅值保持不等于世界向量／力矩永远不更新：yaw旋转、施力点和等效力矩如何随刚体变化由Q3确认。实际力标签对应的是已作用区间还是即将作用区间、事件边界如何标注，在Q4按action-before历史可观测性专门确认，不因本项默认已有正确监督对齐。

局部reset取消该环境两路旧事件并清零，不影响其他环境；新episode起点允许抽样新事件，其上升起点输出为0N，不继承旧episode的残留峰值。每环境每流所需状态为目标向量、启用标记、事件起点／下一计划起点、r／h及当前幅值。状态和随机数恢复在B07中按“新episode重启”语义明确，不在本项承诺恢复PhysX或半个episode。

官方保留项：cmd/ext两路独立抽样、三维目标、零力事件、上升／保持／下降、时长受间隔约束。源码依据为`UniFP/legged_gym/envs/b2/legged_robot_b2z1_pos_force.py:1042-1169`，配置见`b2z1_pos_force_config.py:142-156`。

已确认的工程差异：官方在物理子步循环中调用_push_gripper，以episode_length_buf取模触发；同一策略步episode计数未变，重复调用可能重复抽样。V3按策略边界仅推进一次，并以显式下一事件起点调度，避免重新取模引入重复触发；保持事件机制，但不宣称采样轨迹或有效起点分布逐步等同官方。后续用确定性时钟测试与实际事件trace核验。

确认本项不批准±60N、0.8概率、[3.5,9]s间隔、[1,3]s上升时长或1s保持等具体数值。这些是官方参考，统一到B09讨论，且需验证V3受力范围。

### Q3a：人工外力固定世界方向、命令力使用yaw系，是否沿用官方坐标语义？

状态：2026-11-07用户在坐标转换解释后回复“同意”，确认以下坐标语义；未修改业务代码。施力点和施力API留Q3b。

推荐：事件内部保存世界系人工外力峰值`external_peak_world_n[N,3]`；同一事件的世界方向固定，仅按Q2梯形包络改变幅值。命令力峰值保存在yaw系，仅随底盘偏航旋转到世界系，不随底盘俯仰／横滚倾斜。yaw系X向前、Y向左、Z向上。两路仍独立抽样，世界系人工力不随底盘转向被重新解释。

记`R_yaw(t)`为当前yaw系到世界系的旋转，推荐统一如下关系；所有力均为N，位置为m，K沿用当前逐轴虚拟刚度，数值留后续议题：

```text
external_world(t) = ext_envelope(t) * external_peak_world
command_yaw(t)    = cmd_envelope(t) * command_peak_yaw
external_yaw(t)   = inverse(R_yaw(t)) * external_world(t)
command_world(t)  = R_yaw(t) * command_yaw(t)
compensated_target_world(t)
    = geometric_target_world(t) + (external_world(t) + command_world(t)) / K
```

外力监督和Critic人工外力槽使用当前姿态下的`external_yaw * 0.01`，Actor仍只见命令力而不见人工外力真值。`external_ee_force_y`保留为供现有接口读取的yaw系派生值，不能作为固定世界方向的事件源状态。8个子步复用本策略区间的`external_world`，不重复抽样；构造监督、特权帧和补偿目标时使用对应状态的yaw姿态。具体终止／reset前后的时间配对由Q4确认，本项不预先批准标签时序。

官方依据：`UniFP/legged_gym/envs/b2/legged_robot_b2z1_pos_force.py:1124-1126,1144,1152`直接抽样并向世界force张量写入人工外力，`:130`以GLOBAL_SPACE提交；`:362-366`按当前底盘yaw逆旋转为局部人工力，`:1891-1898`将yaw命令旋转到世界后与世界人工力相加构造补偿目标。

例子：底盘初始朝世界X方向，外力朝世界X方向；底盘左转90°后，实际外力仍朝世界X方向，但yaw系标签变成朝机器人右侧（负Y）。同一时刻，若命令仍为yaw系正X，则其世界方向变为世界正Y。幅值可相同，方向及用途依然不同。

后续单元验证接缝：使用恒等yaw与左转90°姿态核对世界人工力不变、yaw标签变换和命令旋转，并验证由同一状态计算的两种补偿表达等价。具体测试归入B11，本项不确认TCP／COM施力点、额外力矩、幅值或真实接触标签。

### Q3b：是否沿用官方的末端刚体COM施力，不增加TCP偏心力矩？

状态：2026-11-07用户在修正推荐为COM施力后回复“同意”，确认以下COM方案。未实施任何业务代码；Q3a坐标结论不变。

事实：官方调用`apply_rigid_body_force_tensors(..., None, GLOBAL_SPACE)`，人工外力作用在指定末端刚体的COM，没有提交独立力矩。V3任务TCP由`V3TcpKinematics`定义，为arm_seg6 link坐标下`(0,0,0.07961206)m`处；活动V6 URDF中arm_seg6名义COM为`(2.406e-6,-9.4582e-8,-0.038796)m`，二者在该link坐标中相距约0.118408m。该距离只是URDF名义值，Gym若合并固定子体，实际actor COM须以创建时回读为准，不能把刚体状态位置直接当成COM。

原推荐及纠正：此前建议TCP施力，是希望受力点与位置追踪点一致，模拟工具点被推拉；它是另一种物理任务选择，不是将官方方法迁移到V3的必要条件。目前没有证据表明COM施力不能完成B复现，不应仅因点位不同就增加偏心力矩和子步FK。原TCP候选未获确认，现不再作为本轮推荐；保留以下力学说明解释差异，不列入B必做功能。

差异：在TCP施力等价于在实际COM施加同一力F，再施加`tau=(p_tcp-p_com)×F`，力矩单位N·m；COM施力则没有这项附加偏心力矩。例如垂直于10cm力臂的10N力带来1N·m差异，不能宣称动力学等价。COM力仍会通过关节力臂引发机械臂和整机响应，“不额外提交力矩”不代表所有关节力矩为零。

修正推荐：使用`gym.apply_rigid_body_force_tensors(sim, force_tensor, None, gymapi.GLOBAL_SPACE)`；设备端float32力张量逻辑shape为`[N,B,3]`，按Gym全局刚体顺序布局，单位N。仅arm_seg6对应body槽写入`external_world`，其他力槽保持零。每个2.5ms子步提交，8个子步复用同一20ms区间的世界力；SDK负责在当前实际COM施力，不需要提供COM位置张量或额外刷新root／计算TCP来定位外力。力必须逐子步提交，不因幅值相同只提交一次。命令力不进入实际施力张量。

官方保留项：末端刚体COM、世界坐标施力、无独立扭矩张量、逐子步提交；V3必要映射为官方gripper body到V6 arm_seg6。位置奖励仍使用A阶段已确认TCP，不能将位置测量点自动等同于人工外力施力点，报告中明确称末端刚体COM扰动。本项不改质量／惯性／碰撞资产、策略维度或Q3a的坐标语义。

验证接缝：核对仅目标body槽非零、torque参数为None、8子步均提交，局部reset清除对应环境残留力；小刚体COM施力对照检查线动量及无额外偏心力矩；V6实际CPU／GPU非零力短测检查响应、有限性和吞吐。V6有关节约束和地面接触，不能要求整机角运动或关节力矩均为零。容差和规模由B11收束，不为未采用的TCP施力新增必做测试。

### Q4：历史／标签、奖励、终止快照与局部reset如何保持完整时序？

状态：2026-11-07用户要求“Q4请一并讨论”，在展示完整时序与官方对比后回复“同意”，整体确认以下方案。未实施业务代码或改变PPO更新算法。

#### 1. 历史与标签

事实：V3 Runner先调用`alg.act(obs, critic_obs, obs_pred)`，随后`env.step(actions)`，再入库。`V3PPO.act`保存本次输入历史与本次标签，`update`使用配对历史训练decoder，不读取step返回的新标签替换上一条样本。官方Runner／PPO也是先保存同边界历史与obs_pred，再执行物理；官方力在物理子步更新，后续compute_observations以force张量生成标签。当前A力全零，无法仅用A测试暴露未来随机力错配。

推荐：保留同边界历史／标签配对，不改Runner、PPO或缓冲区shape。记策略边界状态为s_t，输入历史H_t以s_t结束；F_t为接下来区间[t,t+1)的实际世界人工力，C_t为Actor本次可见命令力。标签为：

```text
y_t = concat(
    base_velocity(s_t) * existing_scale,
    tcp_spherical(s_t) * existing_scale,
    inverse(R_yaw(s_t)) * F_(t-1) * 0.01,
    zero_base_force[3],
)
store_pair(H_t, y_t)                # 在采样动作时保存，保持现有PPO接口
action_t = actor(H_t)               # 当前命令C_t包含在H_t最新帧内
s_(t+1) = physics(s_t, action_t, F_t) # 8子步的F_t相同，COM施力
y_(t+1).external = inverse(R_yaw(s_(t+1))) * F_t * 0.01
```

含义：速度与TCP标签描述当前状态，人工外力标签描述刚结束的20ms区间中实际提交的力，按当前状态yaw表达。网络是在估计历史对应的已发生受力，不要求提前预测新随机事件；这不保证外力完全可辨识或估计误差为零。已结束事件后的残余运动也不能把旧标签长期延续：一旦刚结束区间实际力为零，标签即为零。

事件源只在Q2指定的策略边界推进一次，当前命令C_t先发布给Actor；已完成区间的`applied_external_world[N,3]`与下一段`pending_external_world[N,3]`分别保存，后者不能覆盖用于当前历史的前者。`external_ee_force_y`作为已完成区间外力在当前yaw下的派生缓存供标签和既有Critic人工力槽使用；step实际提交及本段奖励必须读取本段F_t的快照，不误用上一段派生缓存。两份世界力缓存均为设备端float32、单位N，不新增网络输入或缓冲区字段。

事件刚开始时标签反映实际幅值，不使用尚未达到的峰值；reset后的初始人工外力标签为零，但速度／TCP三维标签仍由新状态计算，不能将12维标签一律置零。人工力监督来源仅为实际提交的人工力，不将命令力、重力、PhysX接触净力或底盘速度push相加冒充真值。

#### 2. 奖励与物理指标先结算

本次20ms区间执行开始时保存命令`commands_t[N,15]`和世界外力`F_t[N,3]`；执行后在真实状态`s_(t+1)`上计算reward、几何／补偿误差和episode统计，然后才推进命令与下一力事件。补偿奖励中的几何目标命令参数与命令力均取本次执行快照，世界外力取本段实际提交值；几何目标世界重建及命令力yaw旋转使用执行结束状态，与原有post-physics求值组织一致，不额外把目标世界点冻结在区间起点。不得先将外力清零、换成下一事件峰值或写入新目标再算旧转移reward。

reward用的外力不取decoder估计；训练监督取注入真值，实际物体接触净力单独记录，不新增独立接触估力任务。原始reward与PPO超时价值补偿分开记录，不以补偿后的训练reward代替实验物理误差。奖励具体项／权重和物理误差输出字段由B08确定，本项固定其输入时序。

#### 3. 后继Critic帧与纯timeout

先完成上述结算及`last_actions=actions_t`，再按A现有组织推进下一边界命令与力事件。后继帧使用真实物理状态`s_(t+1)`、下一段已发布命令`C_(t+1)`、以及刚结束区间`F_t`按`s_(t+1)`的yaw转换后的人工力标签；待施加`F_(t+1)`不填入人工力槽或借补偿目标间接暴露。Critic补偿目标槽用同一后继帧中的几何命令、命令力和`F_t`构造，具体球坐标转换与缩放留B06；这与旧转移reward使用`C_t`的目的不同，文档和测试必须区分。

对done环境，在reset前独立clone `terminal_privileged_obs[K,294]`，由旧Critic历史去掉最老帧并追加真实后继帧，构成3帧快照；不把终止帧先追加到活动历史再重复发布。快照构造复用同一帧接口，避免另写一套终止观测逻辑。普通环境也仅在本边界追加一帧。

保留A已确认语义：`done = terminated OR pure_timeout`；物理失败优先，物理失败与timeout同一步发生时归物理失败。仅pure_timeout使用reset前后继Critic值补`gamma*V_terminal`一次；物理失败不补，done切断跨episode GAE。Runner/PPO保留现有4项step返回和infos接口，不为B新增第二套GAE或终止价值算法。

这里沿用A“结算→推进下一命令→后继快照→reset”的顺序，不把`C_t`一律冻结进后继帧；后继状态是下一次决策的边界，必须与正常连续环境的同边界构造一致。若先reset再取快照，会错误使用新episode的价值。

#### 4. 局部reset与发布下一输入

reset只操作done行：清两路事件、已施加／待施加世界力、yaw力缓存、命令力9:15及施力张量对应行；按A协议恢复root／DOF、动作历史、episode计数、执行系数与位置／速度命令。无物理预热step、不全局清空其他环境力或历史。保留Q2新episode从0N上升语义，下一边界事件只初始化／推进一次，不能在reset和publish重复抽样。

结束环境的32帧Actor与3帧Critic历史先清零，再按A既有噪声／发布规则放入一帧新状态；不能留下旧episode末帧。新episode外力三维标签为零，底盘人工力三维仍为零，速度与TCP标签按新状态计算。未结束环境保留历史，并只追加`s_(t+1)`一帧；其外力标签为刚结束区间实际力。

本次PPO转移仍保存动作前的`H_t/y_t`、本段reward/done以及已clone的终止快照，reset不会覆盖这些已保存量。返回的普通obs／obs_pred对done行属于新episode；不拿它们回填为旧episode的终止状态或辅助标签。终止后继标签不额外增加decoder训练样本，维持每个动作一条配对样本。

正常物理失败保留episode证据后局部reset继续采样，不因单次失败全局停训；NaN／非有限物理状态或执行异常按已有语义终止本轮，不跳过损坏样本伪造完整更新。力时钟沿Q2以episode局部状态推进，恢复新episode策略由B07具体收束。
