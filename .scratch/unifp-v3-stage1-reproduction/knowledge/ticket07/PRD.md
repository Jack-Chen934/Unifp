# 票据07：A阶段测试与启动门控

本任务为V3 A阶段提供最小充分测试汇总和长训启动阻断入口。它承接票据02—06，区分可在纯Torch环境执行的单元测试、依赖Isaac Gym的真实环境测试、512环境训练恢复短测，以及正式环境规模的容量预检；启动判断必须同时核对已确认的A10阈值、当前源码／资产／配置身份及各阶段测试证据。

范围包括：覆盖A11已确认关键契约的缺失单测、32环境Gym冒烟和512环境10轮加跨进程续训证据、正式规模容量证据、面向A8000的只读启动门控，以及按同一A10冻结协议解释正式结果。门控不得启动训练或修改阈值；A10-Q9已确认三组绝对阈值，保存在schema2单文件manifest中；启动就绪须来自当前源码身份下的四阶段真实证据。当前没有A8000 checkpoint，不能给出A阶段效果验收结论。

现有调用链由`train_v3.py`构造V3配置和运行身份、创建环境及Runner，再由Runner按24策略步完成更新、保存和恢复检查点；独立评估链由`evaluate_v3.py`读取显式A8000 checkpoint及manifest。单测已分布在`UniFP_v3/tests/`，实际Gym环境和远程GPU训练依赖Isaac Gym Preview4，不能由`tavis`中的纯Torch测试替代。

开发约束：保持A/B隔离、A阶段末端命令力与外加末端力为零；长训只允许精确完成8000次PPO更新；不自动延长、不启B、不降低门槛。启动门控只检查和汇总证据，不代替真实Gym验收，也不在本票据中自动启动8000轮训练。
