# 02 分部件碰撞代理

已确认总结：按接触功能保留少量盒体、圆柱和低面数凸包，分开保护轮胎、安装间隙、关节活动空间及末端表面。形状预算和误差界限为候选，需通过几何叠图与 Gym 接触验证，用户已确认并要求实施。

## Q1 每个部件如何处理？

| 模块 | 当前 shapes | 推荐代理 | 候选数量 |
| --- | ---: | --- | ---: |
| 底盘 base_link | 143 | 主壳体分区盒体／凸包，四处轮安装组件单独保留语义分组 | 5—8 |
| 机械臂底座 arm_base | 242 | 按主体与安装凸出分区，保留活动间隙 | 2—4 |
| 六个臂段 | 266 | 每段 1—3 个定向盒体／圆柱／低面数凸包，必要时关节壳体单独表示 | 8—18 |
| 两个固定手指 | 46 | 保持外接触面与工具包络的盒体／凸包 | 2—4 |
| 四个滚动轮体 | 24 | 每轮一个以实际轮轴定位的低面数圆柱凸包 | 4 |
| 四个转向机构 | 80 | 分开表示支架两侧／主体，保留轮胎转动间隙 | 8—12 |
| 八个相机／连接件 link | 101 | 各 link 主要实体 1 个盒体或凸包 | 8—12 |

表中基本预算合计约 39—66，给局部间隙修正预留余量，整机目标 40—80。数量是设计预算，不为凑数牺牲必要接触。

## Q2 轮胎如何避免简化后滚动失真？

**推荐：**从当前已验收滚动组的接触包络提取中心、轮轴、有效半径和接触宽度；不用旧 V3 的尺寸。采用沿 link 本地 y 轴的规则圆柱凸包，初始候选为 32 个圆周采样点，两端环共 64 个凸包顶点，显式记录端面与侧面尺寸。其他凸网格同样优先控制在 64 个顶点以内，并检查实际导入／cooking 结果，避免只减少 shape 数却保留复杂凸包。

半径约 0.1m 时，32 边内接截面的理想径向离散误差约 0.48mm；实际包络误差须实测。轮中心、有效半径与接触宽度偏差初定 ≤0.5mm。保持 `replace_cylinder_with_capsule=False`，不把轮胎改为胶囊。若离散滚动产生可见抖动，先比较引擎原生圆柱和低顶点凸包的实际接触结果，不直接堆高面数。

## Q3 如何控制过度包围和漏碰？

**推荐：**代理全部在所属 link 局部坐标建立，位置单位 m、姿态为 URDF rpy rad，不跨 link 合并。不能用一个大凸包封住转向孔、臂段弯折空间或型材内孔。

末端／手指承担接触的外表面偏差候选 ≤1mm；一般外壳主要碰撞表面的偏差候选 3—5mm。采用功能表面定向检查和必要姿态的间隙检查，不要求被省略螺丝／内部零件的所有点都满足统一表面距离。相机、底盘下缘和型材仍保留主体碰撞，避免为提速直接删除有效障碍外形。

候选若出现活动空间被占用或主要表面漏碰，优先局部拆分和修形；不增加全局碰撞豁免。超出本候选预算或需要改变物理容差时，记录原因后再讨论。

## 实施记录：轮拱／轮胎局部保留

依据真实GPU pipeline的隔离对照，轮拱下缘采用原CAD组件逐字节保留，其他新增凸代理维持最多64顶点；轮胎原碰撞保留，每轮轮毂合为一个内缩凸包。最终合计80 shapes，不扩大已有局部过滤。该选择落实本议题“保护活动间隙、局部拆分”的已确认原则，未改变接触容差或算法。原始结果见实验记录 `UniFP_v3/docs/experiments/v3/实验汇总.md`。

# 03 生成与运行接入

已确认总结：新增一个直接的离线资产生成工具，沿用当前 manifest 的计数与局部安装分组接口，尽量复用现有运行链；新资产通过后再切换配置。用户已确认并要求实施。

## Q1 生成调用链和接口是什么？

当前：`桌面 ZIP → build_desktop_asset → 每 CAD 连通件一个碰撞 → v3_a1_desktop`。

目标：`已验收 v3_a1_desktop → build_training_collision_asset → 保留视觉／物性／运动链、按功能生成代理 → v3_a1_desktop_train_v1 → 原 V3 创建链`。

最小接口草图，只有职责和签名，不包含业务实现：

```python
def build_training_collision_asset(source_root: Path, output_root: Path) -> Path:
    # Copy preserved fields; emit named collision proxies and manifest.
    ...

candidate_urdf = build_training_collision_asset(source_root, candidate_root)
candidate_config.asset.file = str(candidate_urdf)
environment = V3PosForce(candidate_config, sim_params, physics_engine, device, True)
```

输出为独立 URDF 路径，目录包含引用的视觉文件、代理凸网格及 `asset_manifest.json`。使用显式盒体尺寸、凸网格坐标和名称表；不建立通用拟合插件、运行期自动切换或多级配置框架。已存在的输出目录不可静默覆盖。

## Q2 如何兼容现有碰撞过滤？

**推荐：**新 manifest 继续提供 `collision_solid_counts[link].count` 和 `source_groups`。底盘四处固定安装件分别输出为 `fl_fixed_collision` 等组，不与主壳体合并；轮体及固定手指保持名称和过滤职责。原 `apply_desktop_assembly_filters` 可据新 count／索引工作，预计无需修改其业务逻辑。

新增近似来源字段记录代理与原 CAD 组件的对应关系，不能把代理组索引伪称为原网格三角面编号。Gym 导入后核对 shape spans，避免 primitive 或 importer 分解使 XML 元素数与实际 shapes 不一致。若既有过滤接口无法表达必要的局部规则，先回写本议题，不直接扩大豁免范围。

## Q3 如何确保碰撞简化不顺带改变惯量？

**推荐：**所有 link 的 URDF inertial 保持原值，分别记录新旧 actor 的实际 mass／COM／inertia；验证包含导入、父类提交和创建期随机化后的结果。

父类现有 `recomputeInertia=True` 路径必须实测核对；若碰撞改变导致实际惯量偏离，不能只凭 XML 一样就验收，也不能默许自动重算。届时记录差异并单独讨论最小 V3 局部修正。本草案不提前修改通用 base 创建链。

## Q4 哪些源码预计涉及？

**推荐：**新增 `tools/build_training_collision_asset.py`、针对候选的必要静态／物理／性能检查；最终接入只修改 `v3_pos_force_config.py` 的资产路径及相关测试入口。原生成器、官方代码、Actor、Critic、PPO 和日志不因这次碰撞优化而重写。

# 04 性能与训练衔接

已确认总结：用同设备短测验证物理收益，再验证4096环境完整更新的实际墙钟速度；保留旧训练，新资产正式复现默认重新起跑。用户已确认并要求实施。

## Q1 性能对照怎么做？

**推荐：**在同一张物理 GPU 顺序运行旧细分资产与新候选的 512 环境、相同 seed 和动作序列。固定 PhysX 参数、局部过滤语义、线程数和域随机化设置；预热后分别记录纯物理段与完整环境 step，使用 CUDA 同步结清。

保持接触容量 `2**25`、倍率5，不同时调整容量、solver、contact offset 或环境数。完整重置 seed 和状态后比较各段，不能再将相继状态下的两个时间段当作精确占比。

候选4096环境进行100轮完整开发更新，保留正常训练日志、统计和阶段末 checkpoint。独立计量预热后的墙钟、采样、更新、写盘与checkpoint开销，报告均值、中位数、P95、GPU总／进程显存和警告。创建耗时单列；短策略状态与正式收敛后的策略不同需注明。

## Q2 性能门槛如何设定？

**推荐：**首要目标为4096完整PPO平均≤4.5秒／轮，对应A8000更新段约10小时。目标未达时报告实测与瓶颈；先局部调整代理数量或凸包复杂度，不靠改训练预算、PPO次数或关闭有效碰撞达标。

数量40—80、轮耗时≤4.5秒和几何误差均为本轮候选验收要求，未测之前不宣称通过。性能未达不否定全部物理工作，但不得直接认定优化完成。

## Q3 旧 checkpoint 能否直接续用？

**推荐：**正式复现从新资产独立seed1零开始；原8000轮日志和checkpoint保留为旧资产实验。碰撞改变会改变接触与状态分布，且现有严格identity明确拒绝跨资产resume，不修改该检查绕过限制。

旧权重未来若用于迁移诊断，应是另行命名的热启动实验，不能等同于新资产从头训练或继承同一计数。本轮不增加热启动入口。

## Q4 当前正在跑的训练怎么办？

**推荐：**方案与候选验证期间不热替换远程r03文件。新候选通过物理／性能验收后，再明确旧运行停止与新正式启动；当前用户只要求先出方案，本轮不停止原训练。

切换后必须重新生成资产／源码／配置身份及对应启动证据，不修改旧报告哈希以假装兼容。冻结的S0／S1／S2任务阈值不随资产优化降低；A通过前仍不进入B或创新阶段。

# 05 单元测试与整体测试

已确认总结：验收覆盖被改变的几何、实际物性、有效碰撞、轮系响应、局部reset和正式规模性能；复用既有测试，不新增每步穷举检查。用户已确认并要求实施。

## Q1 单元测试检查什么？

**推荐：**

1. 新旧visual文件哈希、visual元素、全部joint／inertial及28link／14DOF对应关系一致；不要求collision XML一致。
2. 轮胎中心／轴线／有效半径／接触宽度及TCP接触表面，按02候选精度检查；非关键外壳采用功能包络和间隙检查。
3. 代理名称、归属link、三维凸包有效性、URDF引用文件和manifest组索引一致；检查实际所需的局部过滤映射。
4. 资产身份变化可被已有identity捕获，旧checkpoint严格resume仍被拒绝。

新增或修改函数保持完整类型标注及英文Google风格docstring。只写覆盖真实调用路径和关键回归的测试，不为复制字段或无风险辅助函数逐一镜像测试。

## Q2 整体测试检查什么？

**推荐：**

1. **外观／碰撞叠图：**零位、臂默认位、轮转向代表位、折叠臂接近底盘位；可视化代理侵占间隙或漏掉主要外表面的区域。
2. **32环境物理短测：**接地静置5秒，驱动／转向／臂小动作；检查有限状态、轮系响应、base接触与离地／穿地。实际actor逐link回读质量、COM和惯量。
3. **接触正反对照：**默认姿态无新增非相邻假接触；折叠臂对底盘能真实接触；轮地及末端对简单固定测试物体能接触。测试物体只用于独立诊断场景，不进入正式任务。
4. **局部reset：**4环境中重置一个，不污染其他root、DOF、历史观测或时钟。
5. **512同GPU对照及训练恢复：**性能比较；完整10轮更新＋新进程续1轮，双优化器、物性恢复和计数沿用既有合同。
6. **4096容量与性能：**100轮完整开发更新，正常日志／统计／保存，检查无遗漏碰撞告警，实测轮耗时及显存。

静态／名义条件和随机化条件分开记录；候选零动作失败率不能直接当作训练后S0／S1／S2失败率。短测不要求物理轨迹与旧碰撞模型逐步相等，也不将短训练奖励暂时波动设成新的启动阻断项。

## Q3 何时判定通过或需要返工？

**推荐：**外观、运动链或物性意外改变，必要自碰撞被关闭，轮地／末端接触丢失，新增默认装配穿透，或导入shape／过滤错误，均需返工；不以快代替正确。

几何通过、性能未达则记录剩余成本，局部调整代理后只重测受影响项及必要整体链路。所有结果与原始证据写入单一实验记录，最终只保留成功资产、必要回归和可追溯失败证据，清理本任务中间候选与缓存。

最终依然按既有A8000三组评估判断学习效果，本任务测试不替代该验收。
