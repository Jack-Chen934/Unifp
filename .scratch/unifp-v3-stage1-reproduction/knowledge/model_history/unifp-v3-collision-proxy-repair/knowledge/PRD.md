# V3底盘碰撞代理局部修复

为解决早期策略接近底盘时碰撞代理填充零件间凹隙、提前报告接触的问题，建立独立于当前正式训练资产的候选版本。候选仅把有终止姿态证据的V6 `base_link_proxy_1`从跨CAD部件的大凸包拆成局部凸包，保留全部19个桌面源组件并按用户已确认的固定11组表达；视觉、关节、惯性、初始状态、控制、reward、PPO、自碰撞和终止阈值保持不变。

当前调用链为V3配置资产路径 -> Isaac Gym按URDF创建actor -> PhysX碰撞shape产生base_link接触力 -> 项目沿用的roll／pitch／base接触OR终止。修复候选只改变URDF内base_link的一组19部件凸包及其manifest映射，不自动切换V3配置。

开发完成表示：新目录有独立身份、所有碰撞来源可追溯；保存的失败姿态不再由已定位的跨部件凸包制造目标假相交；其他接触分项保持可见；资产静置、轮系和随机环境短测及原生显示验证通过。候选通过之前不代表可以正式训练，旧8000轮checkpoint不能视作该新资产的验收结果。

用户于2026-11-06要求继续推进统一报告中的P0：离线区分source8/腕部组件以及source99、原proxy13/arm_seg4的视觉与碰撞包络差异。该诊断读取已有终止pose和冻结网格，通过逐侧替换定位几何来源并生成图像、矩阵和来源身份；不修改资产或业务参数。修正具体几何的P2设计不由本次离线诊断自动决定。

随后P1仍属于独立观测：在既有冻结策略回放外增加仿真步结束后的姿态和净力读取，只保存失败前最近两个策略间隔的8×2.5ms记录；原控制、动作、随机化、终止与reset逻辑继续委托既有实现。诊断不执行学习更新，不覆盖冻结源码或既有证据；读取同步可能影响运行时序，故新轨迹必须核对而不能预设与旧结果完全相同。
