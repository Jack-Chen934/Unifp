# 候选修复边界与数据映射

摘要：新建train_v7独立资产，仅把base_link中已证明过宽的proxy_1按桌面CAD原始collision组件映射拆分为19个局部凸包；训练配置不切换，其他物理及策略行为保持不变。候选优先接受几何回归，再进入Gym短测。

Q1：修改哪个碰撞体？

推荐答案：只拆V6当前`base_link_proxy_1`（19个CAD源部件）。step454混合几何对照明确由当前base代理一侧导致相交，且proxy_1在六个冻结复现姿态中出现。旧V1/V5的proxy_13编号不能沿用；V6 shape 13是单一原始组件，step2066的接触另行保留诊断。其他157个全局collision shapes及全部其他link保持相同。

Q2：怎样重建代理？

推荐答案：对桌面URDF中映射到V6 shape 1的19个原始source collision components分别在link-local坐标生成独立凸包，沿用当前训练代理最多64顶点和0.003m支持误差限制。一个跨部件凸包拆为19个局部凸shape，不使用visual取代collision、不加全局间距、不设滤波例外。

Q3：其余流程如何冻结？

推荐答案：从活动V6 r2复制到独立`v3_a1_desktop_train_v7_local_base_proxy`目录。视觉、关节、惯量、所有非目标collision文件、reset、控制、reward、PPO、接触offset和终止1N阈值不变。不改`v3_pos_force_config.py`，不启动训练或正式评估。视频显示的flip问题另行保留为独立已知正式配置问题。

Q4：怎样看待接触余量？

推荐答案：shape contact_offset和rest_offset保持冻结值0.01m／0m。因step158的visual gap仍在1.7mm而桌面base collision本身也与腕部collision相交，候选评估须报告该类边界姿态；不通过提高阈值或降低contact offset隐藏接触。

# 候选验收测试

摘要：验收分单元静态资产合同与整体Gym／PhysX行为两部分；保存的失败姿态要求目标错误凸包相交消失，不要求所有历史形式接触归零。任何真实visual／桌面基准碰撞相交继续单独记录。

Q1：单元层如何验收？

推荐答案：验证源资产identity、target source-component映射无丢失重复、除目标collision网格外link/joint/visual/inertial/dof/limits全部不变；目标每源component恰生成一个有效凸shape，support error<=3mm，所有URDF URI可解析；总shape从158增至176。

Q2：整体仿真如何验收？

推荐答案：冻结实际r03 Gym代码，以新资产路径显式注入独立短测。先零重力静态检查14 DOF、刚体pose和visual正确；再执行原要求静置、底盘正反向和偏航、轮动作、局部reset、多环境短测。至少在原生step454姿态下，V7底盘代理与腕部桌面collision的错误相交须消失；策略sample 128×20s与保留push／关闭push诊断中输出所有失败接触分项。未要求新训练、更新模型或全失败率阈值。

Q3：失败语义和停测如何处理？

推荐答案：沿原V3的局部episode reset和1N判据运行，完整保留物理失败及终止前pose，不加单次失败全局停训。遇NaN、错误DOF、模拟器异常或静置失稳停止测试并保留输出；诊断接触不是自动认定资产未通过。

# 局部凸包分组候选

摘要：用户于2026-11-06听取19个独立凸包与11组局部凸包的区别后回复“同意”，确认保留全部19个目标源部件、组合成固定11组，actor总shape为168。生成正式自包含独立候选，并按最终资产身份重测；活动资产与正式配置继续保持V6 r2。保留全部碰撞判据与V3初始化，不将已有临时短测当作最终训练准入。

## Q1：是否将19个单部件凸包改为11组局部凸包？

推荐：采用以下固定分组：`[8] [10] [23] [25] [57] [99] [92,118] [26,72] [9,94] [42,65,40,93,114] [18,91]`。每个数字是桌面base_link collision的源component索引；全部19个源组件恰好出现一次。组内凸包由原V7单部件凸包顶点并集生成，最大31顶点。只改原V6 base local shape 1对应的19个部件，其他collision、visual、inertial、joint、14 DOF、控制、PPO、reset、接触offset、filter语义和1N终止阈值不变。

原因：当前完整176-shape候选触发GPU PhysX native heap corruption，CPU PhysX通过；临时168-shape分组版本在本机混合与远程完整GPU路径均正常退出，并保留已定位姿态的几何修复效果。168仅是本次实测工作点，不声明PhysX存在统一168-shape硬上限。

代价：组合凸包会填补一些部件间局部凹隙，不能用总量降低或静置通过代替几何检查。必须保留全体历史失败姿态对照及新的策略采样失败分项；没有证据的其他代理问题仍保留。

用户结论：已确认。用户先询问“两者有什么区别”，已说明19个源部件均保留、11组可能填补局部凹隙、当前GPU运行差异与3次剩余接触；随后用户回复“同意”。采用固定11组，继续独立候选生成和验收。此前“prepare前种入DOF”议题已撤回，不实施该初始化改动。

## 当前与目标调用链

当前：V6原shape 1的19个component -> V7的19个凸包 -> actor 176 shapes -> GPU原生崩溃。

目标：同19个component -> 固定11组局部凸包 -> 显式注入独立候选 -> Gym导入168 shapes -> 原有V3控制和物理失败统计。

正式生成器应从V6和桌面源component重建目标数据，并在新目录保存自包含网格、URDF、来源与哈希。临时夹具当前引用V7 r2非目标网格，不直接作为可分发训练资产。

## 数据与失败语义

凸包顶点为base_link坐标系的米制`[V,3]`数组；分组索引是桌面collision组件索引，不是Gym DOF或策略action索引。旧shape到新shape的映射必须同步更新`source_groups`、`proxy_records`、`retained_collision_records`和`visual_clearance_records`。名字、关节角单位和14维action合同不变。

原生异常、NaN、源组件覆盖不完整或非目标物性变化均使候选不通过；物理失败仍按原规则局部reset、保留事件，不改为单次失败全局停训。候选通过也不自动替换正式资产或启动训练。

## Q3：是否先采用0.5mm目标几何外扩裕量？

推荐：对source8／source99／source43的选中局部视觉支持面，先采用0.5mm目标几何外扩裕量；它是独立候选的初值，不是实机尺寸公差，也不是所有表面点到视觉的统一距离上界。不得向内裁掉所选真实视觉结构；若凸化／紧凑化不能兼顾覆盖与目标间距，记录实际偏差，再讨论局部分段或修改裕量。最终验收需同时报告局部支持误差与全部姿态结果，不能只报告生成参数。

用户结论：2026-11-06已确认“采用0.5 mm作为独立候选初值（推荐）”。确认的是目标几何裕量，不豁免实际覆盖／外扩误差报告或后续验收。
