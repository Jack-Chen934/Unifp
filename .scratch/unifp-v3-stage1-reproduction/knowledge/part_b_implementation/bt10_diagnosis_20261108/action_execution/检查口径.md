# 本轮只读诊断口径

已确认的用户方案实施范围为前两项，不包含新的训练对照。

1. 保持原B分布、资产、PD、事件与reset；9000／12000各做mean／sample两条轨迹。动作噪声使用独立固定Generator，各模式同环境seed；reset分歧后不宣称跨轨迹一一配对。
2. 每个物理子步，在同一q／qdot／执行系数下对mean、sample、sample_std9000同时计算原动作映射；只有当前mode对应力矩实际提交。分解结果与原控制器逐子步核对，统计mean与sample共同／噪声新增／均值独有／均无饱和，反事实不是另一条真实轨迹。
3. 保存每策略步的raw动作、目标裁剪、平均P与速度项、限幅前后力矩、全8子步饱和；保存pre／post TCP、几何／补偿目标、world外力、yaw命令力、root、q／qdot、episode与reset。目标前值用本步pending力和当前root，后值用本步applied力和执行后root，避免目标变化混淆。
4. 将误差变化分解为TCP移动与目标移动；该代数分解不是动力学因果。受力onset附近按0.1／0.5／1秒观察，跨reset或其他力事件／目标命令／push的窗口标注或单列，不把物理外力直接推动TCP判成Actor学会补偿。
5. 记录同状态力矩差和同向／反向饱和；方向诊断看移动目标误差与冻结目标投影。瞬时背离不等于策略错误，也不将短期位置响应替代完整B验收。
6. 核验含纯分解器数值边界单测、原生控制器一致性、shape／finite／计数、脚本与存档SHA、正式训练持续及诊断退出；不改任何业务文件。

## 可证伪假设与判断边界

- 优先H1：若探索噪声是即时限幅的重要来源，同状态sample_only会明显出现，降低为9000std的反事实限幅应减小；这只支持即时执行影响，不证明重新训练必然恢复。
- H2：若均值策略本身存在持续不可执行请求，12000均值轨迹的mean限幅也会升高；若mean限幅很低但误差仍大，单靠解除饱和不足修复策略。
- H3：若目标移动混淆了动作方向判断，TCP朝本步起点目标移动占比与相对移动目标的闭合占比会不同；受力窗口需同时展示几何目标移动，不能将world位置位移直接认作控制错误。

背景退化已由上一轮独立128×1000原生采样复现；本轮是在该明确反馈上继续定位，不宣称已经找到或修复根因。两个手算边界单测在远程项目Python通过；本机默认base解释器无torch，未安装依赖、未更改tavis，原生验证使用远程专用环境。

## 复算入口

本机分析：`/usr/bin/python3 analyze_execution.py`，工作目录为本文件所在目录；依赖系统已安装的NumPy和Matplotlib。完整远程原生回放由`run_execution.py`调用`collect_execution.py`，解释器是`/mnt/data_8THDD/conda_envs/unifp_v3_stage1/bin/python`，从冻结源码工作目录启动，GPU3映射为进程内cuda:0。远程路径和PID见`launch.json`，环境变量与上一轮sequential_checks一致。重复原生回放须另设输出目录，不能覆盖本轮身份记录与原始证据。

所有同状态候选均使用实际轨迹的完整观测历史（含实际上一动作），因此均值反事实不是“如果过去一直执行均值动作”的轨迹；旧std候选也不是新的训练模型。候选目标在策略步内固定，P/D项与力矩随8个真实子步q／qdot变化；归档力矩分量是8子步平均值，饱和率保留8子步发生比例，不能把平均力矩当峰值。
